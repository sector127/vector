# საიტის ფოტოები — რა გვჭირდება

ამჟამად საიტზე რეალური ფოტოები არ არის: არქივში სქემებია, ვიზუალიზატორში — რენდერები.
ქვემოთ ჩამოთვლილია, რა ფოტოები გვჭირდება და რისთვის, მნიშვნელობის მიხედვით.

## 1. არქივი — რეალური პროექტები (ყველაზე მნიშვნელოვანი)

- 4–6 **ნამდვილი, დასრულებული** ობიექტი; თითოეულზე 1–3 ფოტო (სასურველია ერთი ღამის, განათებით).
- თითოეულს თან ახლდეს: რა არის, სად (უბანი საკმარისია), ზომა, მასალა, წელი. კლიენტის სახელი — სურვილისამებრ.
- ახლანდელი 6 ბარათი (`src/i18n/locales/*.js` → `archiveProjects`) გაანონიმურებულია, მაგრამ კონკრეტულ სამუშაოებს აღწერს. რომელიც არ გაგვიკეთებია, ამოვიღებთ და რეალურით ჩავანაცვლებთ.

## 2. საწარმო და დანადგარები

- 3–5 ფოტო: ლაზერი, CNC, UV პრინტერი, საამქრო.
- სექცია „საკუთარი საწარმოო დანადგარები“ ახლა მხოლოდ ტექსტია. 2,500 მ² საწარმოს რეალური ფოტო ყველაზე მეტ ნდობას აჩენს.

## 3. გაზიარების სურათი (OG image)

- ჩანს, როცა ბმულს Facebook-ზე, Messenger-ში ან Telegram-ში აზიარებენ. ამჟამად ვიზუალიზატორის რენდერია (`index.html` → `og:image`).
- ერთი შთამბეჭდავი ობიექტის ფოტო, სასურველად ჰორიზონტალური. 1200×630-ზე მოიჭრება.

## 4. ვიზუალიზატორის ფონები (არ არის აუცილებელი)

- 4 რენდერი, რომლებზეც კლიენტის წარწერა ედება (`public/assets/mockups/`). „წინასწარი ხედისთვის“ რენდერი მისაღებია.
- თუ რეალურით ჩანაცვლება გვინდა: **ცარიელი** ფასადი / სითილაითი / ეკრანი / ბილბორდი, ჰორიზონტალური 16:9 კადრი.
- ყოველ ახალ ფოტოზე წარწერის პოზიცია ხელახლა უნდა მოერგოს (`BillboardMockup.jsx`).

## ტექნიკური მოთხოვნები

- ნებისმიერი ფორმატი (JPG, PNG, HEIC); ტელეფონის ფოტოც კარგია. WebP-ში გადაყვანა, მოჭრა და ზომები — ჩვენი საქმეა.
- მინიმუმ 1600px სიგანე. **ორიგინალი**, არა WhatsApp-ით შეკუმშული.
- სასურველია ღრუბლიანი დღე ან ბინდი, ხალხის და მანქანის ნომრების გარეშე.
